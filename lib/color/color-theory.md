# Zarf color theory brief

Working reference for saree recommendations by complexion. Researched April 2026, to be tuned as real recommendations get reviewed. Source links at the bottom.

## 1. Undertone framework applied to South Asian skin

The dominant framework across Indian styling sources is a three-way undertone split (warm, cool, neutral), with **olive treated as a fourth distinct category** in the more serious color-analysis literature. The Western 4-season model has limited resolution for South Asian skin. The 12-season system (which subdivides each season into warm/cool/soft variants) fits better because it separates "deep warm" from "deep cool" rather than lumping all brown skin as "Autumn".

Consensus on South Asian skin specifically:

- Roughly 70% of Indian skin reads warm (golden, yellow, peach); around 30% cool or neutral. Cool undertones are more common than the "brown skin equals warm" stereotype suggests, especially in some South Indian and Tamil complexions.
- Olive undertones are common in Bengali, East Indian, and mixed-heritage skin. Olive behaves like a neutral with a subtle green cast, so it clashes with yellow-greens and mustards but glows in jewel tones.
- High melanin partially masks undertone signals, so the vein/jewelry/sun tests get noisier on deeper skin. Professional drapers score depth (how dark the skin is) and undertone (what hue sits under it) separately. Zarf should do the same.

**Identification tests** (in order of reliability for Indian skin):

1. **Jewelry test** (most reliable). Yellow gold flatters warm; silver/white gold flatters cool; both work for neutral.
2. **White-paper / bare-face test.** Against pure white, skin reads yellow/peach (warm), pink/rosy (cool), grey-green (olive), or balanced (neutral).
3. **Vein test.** Green veins suggest warm, blue/purple suggest cool. Unreliable on deeper skin where veins are hard to see.
4. **Sun reaction.** Tans easily without burning suggests warm or neutral; burns then tans suggests cool.

No single test is decisive. Agreement across two or three is stronger signal.

## 2. Complexion by undertone, palette map

Two axes: **depth** (light, wheatish, deep) and **undertone** (warm, cool, neutral-or-olive). Recommendations below are the consensus across Indian stylist sources. "Light" replaces the older word "fair" here, which in Indian context carries colorist baggage (desirability hierarchy) we refuse to reinforce.

| Bucket | Recommend | Neutral / safe | Avoid | Reasoning |
|---|---|---|---|---|
| **Light, cool** | Emerald, royal blue, ruby red (blue-red), fuchsia, lavender, plum, charcoal | True red, blush pink, navy | Pale pastel yellow, beige, icy peach, washed mustard | Cool skin needs blue-based contrast; warm yellows turn skin sallow |
| **Light, warm** | Coral, peach, terracotta, mustard, olive, warm ivory, rust, marigold | True red, emerald, soft teal | Icy pastels, pure black, blue-based pinks, cold grey | Warm-golden skin glows with fiery/earthy hues; cool pastels drain it |
| **Light, neutral** | Almost all mid-saturation shades; pastel pink, mint, lavender, sage, dusty rose | True red, teal, blush, eggplant | Neon/acid shades that overpower, muddy browns | Balanced undertone, widest range; avoid extremes of saturation |
| **Wheatish, cool** | Magenta, wine, deep teal, sapphire, plum, cool emerald, berry, silver-ivory | Royal blue, burgundy, charcoal | Mustard, orange, camel, ochre, beige | Blue-based jewel tones contrast cleanly; warm earth tones muddy the complexion |
| **Wheatish, warm** | Mustard, rust, terracotta, olive, burnt orange, coral, marigold, warm gold, brick red | Maroon, teal, turquoise, bottle green | Icy pastels, fluorescent pink, cool grey, lilac | Warmth stacks on warmth; earth and spice palettes amplify the natural glow |
| **Wheatish, neutral / olive** | Teal, turquoise, coral, deep magenta, emerald, burgundy, cobalt, plum | Dusty rose, jade, peach, muted red | Yellow-greens (chartreuse), mustard (on olive), pale yellow, grey-beige | Widest flattering range; olive specifically rejects yellow-green which compounds the green cast |
| **Deep, cool** | Sapphire, emerald, ruby, amethyst, cool fuchsia, icy pink, pure white, silver | Royal blue, burgundy, plum | Muted dusty shades, pale peach, mustard, camel | High-contrast jewel tones against deep cool skin read as a Deep Winter palette, luminous |
| **Deep, warm** | Mustard, marigold, burnt orange, rust, bronze, copper, rani pink, golden yellow, deep teal | Maroon, bottle green, ivory | Pure black (blends), dusty pastels, washed lavender, grey | Deep Autumn palette; saturated warm earth and spice tones pop against melanin-rich warm skin |
| **Deep, neutral** | Cobalt, magenta, emerald, gold, saffron, fuchsia, plum, true red | Turquoise, burgundy, ivory | Charcoal/black (blends), low-saturation dusty mid-tones | Saturation beats hue choice; deep-neutral skin punishes muted shades more than it punishes a wrong undertone |

### Cross-cutting rules

- **Contrast matters more than hue for deep skin.** The most cited mistake is reaching for black or charcoal, which blends into deep skin and flattens features. Saturated jewel tones and luminous pastels (ivory, icy pink) both work; mid-saturation muddy browns rarely do.
- **Undertone matters more than hue for fair/wheatish skin.** A blue-red flatters cool fair, an orange-red flatters warm fair. Both look "red" to the eye but one will wash out the wearer.
- **Universal safe bets** (across undertones, assuming reasonable saturation): true red, teal, emerald green, deep magenta, ivory. Use these when undertone data is missing.
- **Olive-specific caveat.** Mustard, chartreuse, and yellow-green are flattering on warm wheatish skin but actively unflattering on olive-undertoned skin of the same depth. This is the single biggest case where "wheatish" without an undertone tag gives wrong answers.

## 3. Day vs night does change recommendations

Consensus from stylist sources:

- **Day (natural light):** lighter, softer hues. Pastels, ivory, peach, mint, powder blue, soft gold. Natural sun makes fully saturated jewel tones read heavy or dull, and makes metallics look brassy.
- **Night (artificial light):** deeper jewel tones and metallics. Wine, emerald, sapphire, ruby, bronze, antique gold. Low warm indoor lighting flattens pastels and boosts saturation, so deeper colors actually read truer.

**Important:** day/night modulates *saturation and finish*, not the underlying undertone rule. A cool-undertoned woman still wants blue-based reds at night (ruby) and blue-based pastels in the day (lavender, powder blue), not orange-based versions of either. Treat time-of-day as a saturation/finish filter on top of the undertone palette, not as a replacement.

**Caveat:** this is consensus stylist advice, not rigorously sourced. The physics (incandescent light pulls colors warm and darkens pastels) is real; the specific color recommendations are taste-adjacent.

## 4. Where the internet disagrees

- **Is olive its own undertone or a warm sub-type?** Most retailer blogs fold olive into warm. Professional color-analysis sources treat it as distinct because its avoid list is different (yellow-greens specifically). **Zarf treats olive as distinct.**
- **Does fair skin need deep colors or pastels?** Sources split roughly 50/50. The accurate answer from the 12-season framing is that fair cool skin wants jewel tones, fair warm skin wants earth tones, and only fair neutral skin has the full pastel range as a true strength. Retailer blogs over-generalize to "fair skin equals pastels".
- **"Universal" colors.** Royal blue, emerald, and maroon are cited everywhere as universal. In practice, maroon on cool fair skin and royal blue on warm wheatish skin are both mediocre calls. Treat "universal" labels skeptically; prefer to tag each saree with a specific palette.
- **Missing primary sources.** Vogue India, Harper's Bazaar India, and Femina do not appear to have a canonical published "skin tone by saree color" editorial. Most stylist guidance circulates via retailer blogs and Instagram. Flag this in the product: the expert's eye is still the gold standard; this framework grounds but doesn't replace her.

## 5. Proposed tagging schema

### 5a. User-side: 9 complexion buckets (3 by 3 grid)

```
depth ∈ {fair, wheatish, deep}
undertone ∈ {cool, warm, neutral_olive}
```

The 9 buckets: `light_cool`, `light_warm`, `light_neutral`, `wheatish_cool`, `wheatish_warm`, `wheatish_neutral`, `deep_cool`, `deep_warm`, `deep_neutral`.

Collapse olive into `neutral_olive` rather than creating a 4th undertone column. Keeps the grid to 9 cells and adds one extra avoid-rule (yellow-greens) on that bucket. Allow the user to pick "not sure" for undertone; fall back to neutral plus universal-safe colors.

### 5b. Saree-side: 14 color families

Each saree gets tagged with 1 to 3 `color_family` values plus a `saturation` (muted, mid, vivid) and `tone` (warm, cool, neutral) attribute on its dominant color. Families:

```
red_warm          (tomato, brick, vermilion)
red_cool          (ruby, crimson, berry)
pink_cool         (rani, fuchsia, magenta)
pink_warm         (coral, peach, blush-peach)
orange_earth      (rust, terracotta, burnt orange)
yellow_warm       (mustard, marigold, ochre, golden)
yellow_cool       (pale lemon, icy yellow)     # rare on sarees
green_warm        (olive, moss, chartreuse)
green_cool        (emerald, bottle, forest, teal-leaning-blue)
blue_cool         (royal, sapphire, cobalt, navy)
blue_warm         (turquoise, peacock, teal-leaning-green)
purple            (plum, aubergine, lavender, amethyst)
neutral_warm      (ivory, cream, beige, gold, bronze, camel)
neutral_cool      (white, silver, charcoal, grey, black)
```

### 5c. Scoring

For each complexion bucket, maintain two lists: `flatter` and `avoid`. Both reference `color_family` values. The recommended palette mapping distilled from section 2:

```
light_cool:       flatter=[red_cool, pink_cool, blue_cool, green_cool, purple, neutral_cool]
                 avoid=[yellow_warm, orange_earth, neutral_warm(beige only)]
light_warm:       flatter=[red_warm, pink_warm, orange_earth, yellow_warm, green_warm, neutral_warm]
                 avoid=[pink_cool(icy), blue_cool(icy), neutral_cool(pure black)]
light_neutral:    flatter=[red_cool, red_warm, pink_cool, pink_warm, purple, green_cool, blue_cool]
                 avoid=[]  # widest range
wheatish_cool:   flatter=[red_cool, pink_cool, purple, blue_cool, green_cool, neutral_cool]
                 avoid=[orange_earth, yellow_warm, green_warm, neutral_warm(camel)]
wheatish_warm:   flatter=[orange_earth, yellow_warm, green_warm, red_warm, pink_warm, neutral_warm]
                 avoid=[pink_cool(icy), blue_cool(icy), purple(lavender), neutral_cool]
wheatish_neutral: flatter=[red_cool, pink_cool, blue_warm, green_cool, purple, orange_earth]
                 avoid=[yellow_warm(on olive), green_warm(chartreuse on olive)]
deep_cool:       flatter=[red_cool, pink_cool, blue_cool, green_cool, purple, neutral_cool(white/silver)]
                 avoid=[yellow_warm(muted), neutral_warm(beige), neutral_cool(pure black)]
deep_warm:       flatter=[orange_earth, yellow_warm, red_warm, pink_cool(rani), blue_warm(teal), neutral_warm(bronze/gold)]
                 avoid=[neutral_cool(black/charcoal), dusty mid-tones of any family]
deep_neutral:    flatter=[red_cool, red_warm, pink_cool, blue_cool, green_cool, yellow_warm(saturated)]
                 avoid=[neutral_cool(black), any low-saturation muddy family]
```

**Score function** (proposal for `lib/recommendation/`):

```
score(saree, user):
    base = 0
    if saree.dominant_family in bucket.flatter: base += 2
    if saree.dominant_family in bucket.avoid: base -= 3
    for secondary in saree.secondary_families:
        if secondary in bucket.flatter: base += 0.5
        if secondary in bucket.avoid: base -= 1
    # saturation modifier
    if user.depth == "deep" and saree.saturation == "muted": base -= 1
    if user.depth == "fair" and saree.saturation == "vivid" and user.undertone == "warm": base -= 0.5
    # day/night modifier (passed separately)
    if event == "day" and saree.saturation == "vivid": base -= 0.5
    if event == "night" and saree.saturation == "muted": base -= 0.5
    return base
```

Mechanical enough to compute without per-saree human judgment, while still deferring to hand-tagged dominant/secondary color families, which is the curation quality bar PRD section 4 asks for.

### 5d. Implementation notes for `lib/color/`

- Store each saree's color info as: `{dominant_family, secondary_families[], saturation, tone, has_contrast_border}`. The last field matters because a deep-skinned user often benefits from contrast-border sarees even if the body color is ambiguous.
- Store user complexion as: `{depth, undertone, confidence}` where confidence is how many undertone tests agreed. Low-confidence users get the "neutral" column of their depth row by default, which is the safest fallback.
- Keep the `flatter`/`avoid` maps in a single versioned JSON file so the stylist can tune them without code changes.

- [Fabilicious Fashion, Day vs Night Wedding Sarees](https://www.fabiliciousfashion.com/en-us/blogs/news/day-vs-night-wedding-sarees-for-guests-how-to-dress-right-for-the-occasion).
